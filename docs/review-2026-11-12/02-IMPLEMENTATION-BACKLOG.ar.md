# خطة التنفيذ والقبول لكورسر

نفّذ من المستودع الحالي، مع المحافظة على تغييرات صاحبه. المرجع الوظيفي [مواصفات النظام](01-SYSTEM-SPEC.ar.md)، ومرجع العيوب [المراجعة](00-TECHNICAL-REVIEW.ar.md). كل بند هنا دفعة قابلة للمراجعة؛ لا تعدل جميع المجالات في PR واحد ولا تعتبر رسم صفحات فارغة إتمامًا.

## مراحل التسليم

- **M0 — أساس قابل للفحص:** BHD-001 إلى006. بيئات وجودة وبيانات وحسابات ومؤسسات وملفات آمنة. لا إطلاق مالي.
- **M1 — سوق حقيقي:** BHD-007 إلى009، ثم الحد الأساسي من011 و012 و013. يستطيع فرد ومعرض نشر إعلان عبر مراجعة الإدارة وتلقي تواصل فعلي.
- **M2 — تثمين وفحص عاملان:** BHD-010 إلى015 مكتملة. طلب من العميل → توزيع → قبول شريك → تقرير → متابعة. هذا أول إطلاق تجريبي موصى به، بخدمات محددة في عمان افتراضًا.
- **M3 — المعاملات والشركاء الماليون:** BHD-016 ثم017 و018، كل مزود يُفعل منفردًا بعد اختبار sandbox وUAT وعقده. منصة assisted مقبولة إذا كانت العمليات حقيقية ومعلنة؛ لا تحمل عبارة «ربط مباشر» قبل الربط.
- **M4 — أنشطة إضافية:** BHD-019 إلى023، تفعيل تدريجي لكل نشاط بعد معايير قبوله والتشغيل اللازم.
- **M5 — الإطلاق والتوسع:** BHD-024 بوابة إلزامية لكل إطلاق، ثم025 حسب مؤشرات الاستخدام.

تُطبق بوابة الجودة والأمان في كل مرحلة، ولا يؤجل إصلاح عزل المؤسسات إلى M5. هذه خريطة ترتيب وليست وعدًا بتاريخ؛ بعد BHD-003 يقدم المنفذ تقديرًا بالتكلفة/أيام العمل لكل دفعة، ويحدثه بعد أول دورة مكتملة. مدد اعتماد الشركاء والحصول على APIs مسار خارجي مستقل عن كتابة الكود.

## BHD-001 — تثبيت خط أساس وأدوات الجودة

**الاعتماد:** لا شيء. **يعالج:** F12.

العمل والملفات:

- تصوير git status والتغييرات الحالية في سجل تسليم دون نسخ أسرار. لا reset أو clean ولا تعديل assets خارج الدفعة.
- إعداد `eslint.config.mjs` متوافق مع النسخ الفعلية، وتغيير script lint إلى ESLint CLI غير تفاعلي. إضافة `typecheck` وscripts اختبار ذات غرض وCI مناسب للاستضافة/المستودع المتاح، ومثال `.env.example` بأسماء متغيرات وقيم وهمية فقط.
- إنشاء test harness لوحدات قواعد الأعمال، integration على PostgreSQL مؤقت منفصل، وPlaywright لرحلات E2E؛ لا مئات اختبارات snapshot للمكونات الساكنة.
- `docs/runbooks/local-development.md` يصف npm ci وDB والاختبار وstaging. pin Node LTS متوافق بعد التحقق من وثائق النسخ.

القبول: checkout نظيف +`npm ci` يعمل؛ lint وtypecheck وbuild بلا أسئلة؛ فشل اختبار أعمال مقصود يفشل CI؛ secrets لا تدخل bundle أو logs. اختبار baseline يشمل empty finance offers و404 كاختبارات انحدار ستصبح خضراء مع دفعات الإصلاح؛ لا يكسر main باختبارات معروفة الفشل دون عزل واضح.

تسليم المراجع: نسخ Node والحزم وأوامر النتائج وملفات الإعداد والتغيرات الناتجة من formatter إن وجدت منفصلة عن منطق الأعمال.

## BHD-002 — ترقية الاعتماديات ومعالجة audit

القبول: إعادة audit لشجرة runtime والتطوير وتوثيق أي استثناء بشروطه ومالكه وموعده؛ لا high/critical غير معالج في مسار الإنتاج المطبق؛ build وtypecheck وlint وsmoke للصفحات الرئيسية والبيع والسوق يعمل. لا تكتفِ بتغيير رقم package.json دون lockfile والتحقق من النسخة المثبتة.

## BHD-003 — PostgreSQL والمخطط والترحيلات

**الاعتماد:**001،002. **يعالج:** F01 وF02 وF03.

العمل: `prisma/schema.prisma` وmigrations و`src/server/db` وrepositories لوحدات identity/organizations/catalog/marketplace/requests/audit/outbox. ابدأ بالجداول المستخدمة في M1/M2 فقط ثم أضف الامتدادات مع دفعاتها. قواعد المفاتيح والملكية وunique وXOR والمبالغ/timezone كما في spec.

استيراد البيانات الثابتة إلى seed تطوير منفصل بوسم demo، وترك الصور/الأسماء غير الموثقة خارج الإنتاج. لا تستورد طلبات localStorage كدليل استلام أو موافقة أو مزايدة. يمكن لاحقًا استيراد مسودة يراجعها صاحبها مع إعادة تحقق وصريح opt-in.

القبول: DB فارغ يهاجر ويزرع ثم يمسح في test فقط؛ قيد الملكية يمنع المالكين المتعارضين؛ قيد مبلغ يمنع قيمة غير صالحة؛ FK تمنع إسناد فرع مؤسسة أخرى؛ التواريخ تحفظ UTC؛ migration مع خطة rollback ولا destructive migration على بيانات حية.

## BHD-004 — الحساب والجلسات والمصادقة

**الاعتماد:**003. **يعالج:** F02.

العمل: `src/server/auth` ومسارات المكتبة و`src/app/(auth)` وسياسات sessions، شاشة دخول/تحقق/استرداد، حماية `/account`، MFA للإدارة/الشركاء، adapters لإرسال SMS/بريد. dev adapter موثق ولا يقبل رموز اختبار في الإنتاج.

القبول:

1. تسجيل ودخول وخروج واسترداد والتحقق يعملون على staging بمزود اختبار مناسب.
2. OTP منتهي أو مستخدم أو تجاوز محاولات يرفض؛ الانتقال من بريد غير متحقق لا يربط حسابين لشخصين دون إثبات.
3. إبطال جلسة/تعليق حساب يسري على API، لا الصفحة وحدها؛ اختبار CSRF/origin وopen redirect.
4. لا بيانات حساب في localStorage كمصدر مصادقة؛ تظل prefs/مقارنة ضيف مسموحة بعد validation.

## BHD-006 — رفع الملفات ووثائق العميل

**الاعتماد:**005. **يعالج:** F03 وF12.

## BHD-007 — الكتالوج والأسواق والعملة واللغة

**الاعتماد:**003،006. **يعالج:** F07 وF08 وF09 وF10 وF13.

## BHD-008 — السوق والبحث وتفاصيل الإعلان

## BHD-009 — نشر وإدارة الإعلان الفردي والحوادث

**الاعتماد:**005،006،007،008. **يعالج:** F03 وF09.

العمل: ربط `sell-wizard.tsx` و`accident-wizard.tsx` بـListing draft وVehicle وmedia وdisclosure؛ autofill من API VIN موثوق أو إدخال يدوي مع provenance؛ لا زر VIN وهمي. autosave وresume وpreview وsubmit moderation مع optimistic versioning. لوحة حساب إعلانات أساسية ومسار مراجعة إدارية.

القبول: من جهازA ينشئ draft بصور، من جهازB يكمله؛ submit لا ينشر قبل review؛ قبول مراجع ينشر في `/cars`؛ رفض يبقي سببًا؛ تعديل حساس يستلزم revision؛ سعر سلبي أو year/model غير متوافق يرفض على API؛ حالة حادث وغرق/حريق/وسائد واضحة؛ الإفصاح عن clean title لا يزيل وسم الضرر. لا يولد رقم الطلب المحلي إعلانًا تلقائيًا.

## BHD-010 — محرك الطلبات والتوزيع والمهام

**الاعتماد:**005،006،007. **يعالج:** F01 وF05.

العمل: `src/modules/requests` وrouting/quotes/consents/assignments/events؛ jobs/outbox worker، service rules، idempotency، SLA وتقويم وأقل مشاركة بيانات. استبدال `addRequest` في مجال واحد أولًا ثم بقية المجالات عند تنفيذها. لا إبقاء واجهة تقول إن الطلب أرسل بينما تسلك localStorage.

القبول:

1. حفظ الطلب والتكليف وoutbox ذري؛ قطع العملية بين الخطوات لا ينتج رسالة بلا طلب أو طلبًا مفقود الإسناد دون إمكانية استدراك.
2. مثمن مرخص مؤهل يأخذ الطلب، وآخر منتهي أو خارج المدينة يستبعد بسبب مسجل.
3. timeout/رفض يوزع مرة واحدة إلى التالي؛ قبول متزامن عند إعادة الإسناد لا يعطي جهتين مهمة نهائية.
4. retry بنفس المفتاح ينشئ طلبًا واحدًا؛ نفس المفتاح مع payload آخر409.
5. لا مرشح → طابور تشغيل وحالة صادقة؛ failed SMS → retry/dead-letter والطلب يظل موجودًا.
6. قبول عرض منتهي أو ليس للطلب/العميل نفسه يرفض؛ race قبول عرضين ينتج قبولًا واحدًا حيث الخدمة أحادية.

العمل يشمل Conversation/Participants ورسائل وتذاكر وقنوات رد حقيقية وإعدادات notifications. تحديث Contact/About/Sell/الرئيسية لإزالة المنافسين و`.example` والوعود غير المحققة؛ بيانات الشركة التجارية من مالكها ولا تُختلق.

القبول: مستخدم يرى طلبه ومراحله ورسالة شريك من جهاز آخر، ويرفع نقصًا ويقبل عرضًا ويلغي ضمن السياسة؛ لا يشترك طرف بمحادثة بتعديل ID؛ تغيير prefs لا يمس وثائق؛ البحث المحفوظ يرسل فقط بإذن وحدود تكرار؛ ticket يظهر للدعم ويمكن الرد عليه؛ شاشة غير متاحة تعرض سببًا بدل نجاح وهمي.

## BHD-012 — لوحة إدارة التشغيل والموقع

## BHD-014 — التثمين التلقائي والتقرير المعتمد

**الاعتماد:**010،011،012،013. **يعالج:** F05 وطلب التثمين الأساسي.

## BHD-016 — الدفع والفواتير والعمولات والتسويات

**الاعتماد:**010–013. **يعالج:** فجوة المال لكل المجالات.

العمل: adapters إلى PSP معتمد فعليًا في السوق ونوع الخدمة، PaymentIntent/Attempt/Refund/Invoice/Ledger/Settlement/ProviderEvent، outbox، signature validation، حالات ومصالحة وواجهة حساب وإدارة مالية. لا اختيار مزود من الاسم وحده قبل التحقق من دعم نشاط المزادات والضمانات والاسترداد ومتطلبات merchant.

القبول:

- السعر يقرأ من accepted snapshot خادميًا؛ body معدل إلى1 بيسة لا يغير المستحق.
- webhook مكرر/مقلوب ترتيبًا/متأخر وredirect مزور لا يضاعف القيد أو الخصم أو التسليم.
- مبلغ/عملة/merchant غير مطابق يوقف التسوية ويطلق تنبيهًا؛ timeout غير مؤكد يستعلم ويصالح قبل محاولة جديدة.
- refund partial/full لا يتجاوز المدفوع ناقص المسترد؛ موافقة ثانية للحدود الحساسة؛ تعديل مستفيد موثق.

- UAT sandbox مع أدلة مزود، runbook لتسوية ناجحة وتعويض فشل جزئي وتوقف callbacks. Live flag يبقى مغلقًا دون merchant وعقد ومفاتيح حقيقية وموافقات التشغيل اللازمة.

## BHD-024 — بوابة مراجعة الإطلاق لكل مرحلة

**الاعتماد:** الوحدات التي ستطلق؛ تنفذ أجزاءها مع كل دفعة ولا تنتظر اكتمال كل المجالات.

الفحوص والأدلة الإلزامية:

1. **جودة الكود:** npm ci وlint وtypecheck وunit/integration وbuild؛ migrations من DB فارغ ومن نسخة بيانات مجهولة الهوية مشابهة للإنتاج. كل نتيجة مرتبطـة بـcommit SHA.
2. **رحلة كاملة:** E2E العميل+الإدارة+الشريك، نجاح وفشل وإلغاء واسترداد عند وجود أموال. لا mocks في إثبات التكامل الحقيقي؛ mocks مسموحة للاختبار وتوسم بوضوح.
3. **العزل:** cross-user/cross-org/cross-branch/cross-market وملفات وتصدير ومحادثات وcache، وسحب جلسة/اعتماد، مع أدلة من API لا screenshots فقط.
4. **التحمل:** provider timeout وrate limit وwebhook replay/out-of-order وjob crash وإعادة تشغيل، event dedup، ملفات مرفوضة، انقطاع شبكة وحفظ نموذج.
5. **الأداء:** seed اختبار10,000 إعلان، فهارس وخطة استعلام،100 مستخدم قراءة متزامنًا افتراضًا أوليًا؛ هدف p95 API البحث≤800ms داخل region محددة يستثني زمن الإنترنت ويذكر DB/الجهاز/dataset/نافذة القياس. لا تتحول هذه الفرضيات إلى ادعاء حمل إنتاج مثبت.
6. **الواجهة:** لقطات وفحص تفاعلي360/768/1440px، عربي/إنجليزي، keyboard/screen reader لعينة journeys وaxe؛ sliders/modals/uploads/filters/sticky elements لا تمنع الاستخدام. تأكيد WCAG يحتاج فحص يدوي، لا badge بناءً على أداة واحدة.
7. **SEO:** HTML language/metadata/canonical/hreflang/status404 وسجل redirects وsitemap وrobots، لا بيانات خاصة أو إعلانات قيد مراجعة في الفهرسة.
8. **أمان واعتماديات:** audit محدث، فحص أسرار، CSP/headers وسياسة الملفات والجلسات، أي استثناء محدد بشروطه وموافقة صاحبه؛ لا تقرير «آمن100%».
9. **تشغيل:** تنبيهات وأرقام correlation، runbooks للدفع/الإصدار/الإسناد/النسخ/الاستعادة، تدريب موظف وشريك، تجربة إعادة استعادة معزولة ونتيجتها وRPO/RTO المقاسان.
10. **تجاري:** شريك حقيقي ومخول لكل نشاط مُفعّل، أسواق وشروط وبيانات شركة وموافقات وقنوات دعم وعقود مزود ملائمة. إن لم تكتمل، تبقى الخدمة disabled/assisted الحقيقي وفق نطاقها وتظهر حالتها الصادقة.

يصدر المنفذ قائمة PASS/FAIL/BLOCKED لكل معيار مع السبب والأثر؛ لا يعلن اكتمال دفعة بها إجراء أساسي placeholder أو اعتماد خارجي غير متحقق.

## BHD-025 — تحسينات المنافسة بعد القياس

**الاعتماد:** M2 ومؤشرات فعلية؛ المالية تتطلب016 حيث تستخدم.

تُقيّم ميزات البحث الطبيعي وتنبيهات السعر ومرآب الصيانة وEV battery reports والتبادل وخدمات النقل والأساطيل وB2B والتسعير الإحصائي بحسب حجم طلب وجودة بيانات وتكلفة التشغيل. لكل ميزة hypothesis وmetric وخط أساس وتجربة صغيرة، وليست قائمة وعود داخل الرئيسية. لا تبدأ ML للتثمين قبل بيانات مقارنات كافية وسجل نتائج وتقسيم اختبار وخطأ مقاس وحدود الثقة.

كود المجال + واجهة الأطراف التي تحتاجه + تحقق خادمي + صلاحيات + حالات فشل + تخزين فعلي + tests مناسبة + migrations موثقة + واجهة عربية/إنجليزية + تشغيل staging + دليل مراجعة. الصفحة التي تعرض بيانات ثابتة أو زرًا يكتب محليًا فقط لا تحقق التعريف، حتى لو نجح build.
